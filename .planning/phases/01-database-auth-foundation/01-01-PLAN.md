<task type="auto">
  <name>Task 1: Create agency RPC functions migration</name>
  <files>Soundflare/database/add_agency_rpc_functions.sql</files>
  <action>
Create SQL migration file with two RPC functions following the exact signatures from the research document:

1. `public.agency_metrics(start_date date, end_date date)` -- SECURITY DEFINER, STABLE, LANGUAGE sql
   - JOINs soundflare_agents -> soundflare_projects, LEFT JOIN soundflare_call_logs (date filtered), LEFT JOIN call_reviews (status='completed')
   - Returns: agent_id, agent_name, organization_name, call_date, total_calls, total_minutes, failure_count, failure_rate
   - GROUP BY agent, date; ORDER BY call_date DESC NULLS LAST, agent_name
   - Default date range: last 30 days

2. `public.agency_failures(start_date date, end_date date, error_type text)` -- SECURITY DEFINER, STABLE, LANGUAGE sql
   - JOINs call_reviews -> soundflare_call_logs -> soundflare_agents -> soundflare_projects
   - Filters: status='completed', error_count > 0, date range, optional error_type filter
   - Returns: call_log_id, call_id, agent_id, agent_name, organization_name, call_started_at, duration_seconds, error_classification, has_api_failures, has_wrong_actions, has_wrong_outputs, error_count
   - error_classification CASE: MULTIPLE (2+ types), API_FAILURE, WRONG_ACTION, WRONG_OUTPUT, UNKNOWN

3. Permission grants for BOTH functions:
   - REVOKE EXECUTE FROM PUBLIC, anon, authenticated
   - GRANT EXECUTE TO service_role

4. Performance index:
   - `CREATE INDEX IF NOT EXISTS idx_call_logs_agent_created ON public.soundflare_call_logs(agent_id, created_at)`

Use the exact SQL from the research code examples section. The research was derived from inspecting the actual schema.

Run the migration: `docker exec soundflare-db psql -U postgres -f /dev/stdin < Soundflare/database/add_agency_rpc_functions.sql`
Then restart PostgREST and Kong to pick up schema changes: `cd /root/projects/Soundflare2/Soundflare && docker compose restart rest kong`

<task type="auto">
  <name>Task 2: Create Slack notification tables migration</name>
  <files>Soundflare/database/add_slack_notification_tables.sql</files>
  <action>
Create SQL migration file with two tables following the exact schema from the research document:

1. `public.slack_notification_configs`:
   - id uuid PK DEFAULT gen_random_uuid()
   - agent_id uuid NOT NULL REFERENCES soundflare_agents(id) ON DELETE CASCADE
   - webhook_url text NOT NULL
   - is_enabled boolean NOT NULL DEFAULT true
   - created_at timestamptz NOT NULL DEFAULT now()
   - updated_at timestamptz NOT NULL DEFAULT now()
   - UNIQUE constraint on agent_id
   - RLS ENABLED, NO policies (service_role only)

2. `public.slack_notification_log`:
   - id uuid PK DEFAULT gen_random_uuid()
   - config_id uuid NOT NULL REFERENCES slack_notification_configs(id) ON DELETE CASCADE
   - agent_id uuid NOT NULL REFERENCES soundflare_agents(id) ON DELETE CASCADE
   - call_log_ids uuid[] NOT NULL (UUID array, not text array -- per Pitfall 6)
   - status varchar(20) NOT NULL DEFAULT 'sent' CHECK (status IN ('sent', 'failed'))
   - error_message text
   - sent_at timestamptz NOT NULL DEFAULT now()
   - RLS ENABLED, NO policies

3. Indexes:
   - idx_slack_notification_log_agent_id ON slack_notification_log(agent_id)
   - idx_slack_notification_log_sent_at ON slack_notification_log(sent_at)
   - idx_slack_notification_log_config_id ON slack_notification_log(config_id)

4. Explicit grants (per Pitfall 3 -- don't rely on default privileges):
   - GRANT ALL ON both tables TO service_role
   - No grants to anon or authenticated

Run the migration: `docker exec soundflare-db psql -U postgres -f /dev/stdin < Soundflare/database/add_slack_notification_tables.sql`

  </verify>
  <done>Both slack_notification_configs and slack_notification_log tables exist. RLS is enabled on both. No anon/authenticated policies exist. service_role has ALL privileges. Foreign keys to soundflare_agents cascade on delete.</done>
